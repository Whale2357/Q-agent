## 0. 문서 통합 원칙 (무엇을 남기고 무엇을 버렸는가)

기존 초안·이론 조사(`기획안 초고`, `기획안_1`, `기획안_1.1`, `기획안_3`, `질문이론`, `질문이론 기획안`, `질문 이론_2`)는 **같은 문제를 다른 층위에서 본 것**이었으며, 본 문서로 통합한 뒤 개별 파일은 삭제했다. 충돌처럼 보이던 부분은 아래처럼 정리했다.

| 층위 | 남은 핵심 | 출처 | MVP 반영 |
| --- | --- | --- | --- |
| **왜** 질문이 필요한가 | Team Reflexivity / Guided Reflexivity | 기획안_1 | 서사·포지셔닝 |
| **언제** 개입하는가 | 병목(Bottleneck) + 중단점 이론 | 기획안_1, 질문이론 기획안 | MVP는 **수동 트리거** (자동 타이밍은 v1.5) |
| **무엇을** 묻는가 | Questioning Operator + 회의 목적별 역할 | 기획안_1.1/3, 질문이론 | MVP는 **의사결정·문제해결 2종 프리셋** |
| **어떤 질문이 좋은가** | EVPI(정보이득) + INQUISITIVE(비중복) | 초고, 질문이론 기획안 | **채점 파이프라인 핵심** |
| **가정을 어떻게 드러내는가** | PREG 트리거 + Toulmin warrant | 초고(3번 기준), 질문이론 기획안 | **생성기 쪽**으로 이동 (독립 스코어 축 아님) |
| **어떻게 말해야 하는가** | 정중함 4단계 + 심리적 안전 | 초고, 질문이론_2 | **톤 다이얼** |

**정리된 공식**

```
회의 상태 → (병목/목적 인식) → 후보 질문 생성(PREG) → 필터(INQUISITIVE)
        → 가치 채점(EVPI) → 톤 변환 → 임계값 통과분만 제시 / 아니면 의도적 반려
```

초고의 “3대 스코어링” 중 **가정 노출**은 “좋은 질문의 종류(생성 트리거)”로 내리고, 채점 축은 **가치·신규성·안전(톤)** 으로 재정렬한다. 이것이 이론과 구현이 가장 덜 충돌하는 구조다.

## 1. 문제 정의

### 1.1 현상: “질문 없는 회의실”
- 참석자는 **인지적 맹점**(무엇을 놓쳤는지)을 스스로 보기 어렵다.
- 심리적 두려움·체면 위협으로 **질문 자체를 주저**한다.
- 결과: 공유된 정보만 반복(히든 프로파일), 성급한 합의, 잘못된 문제 정의에 대한 “정답”만 양산.

### 1.2 기존 AI의 한계
- Zoom AI Companion 등 회의 보조 AI는 **요약·액션아이템·질문 생성**까지 한다.
- 그러나 **“무엇이 좋은 질문인가”의 명시적 평가층(Evaluation Layer)** 이 약하다.
- 증상: 답이 이미 나온 중복 질문, 뻔한 확인 질문, 사람을 공격하는 위협적 질문 반복.

### 1.3 우리가 푸는 한 문장
> **질문을 ‘더 많이’ 만드는 것이 아니라, 팀이 지금 멈춰 성찰해야 할 *단 하나의 질문*을 골라 안전하게 건넨다.**

이론적으로 이는 Edmondson의 Team Learning Behavior 중 “질문하기”를, West/Schippers의 **Guided Team Reflexivity** 개입으로 자동화하는 것이다.

## 2. 솔루션: Q-Agent

### 2.1 제품 한 줄
**Q-Agent**는 회의/대화 텍스트 맥락을 읽고, 후보 질문을 생성한 뒤 **채점·필터·톤 조절**을 거쳐 “지금 던질 가치가 있는 질문만” 큐레이션하는 인지 증강 서비스다.

### 2.2 차별점 (심사 한 장 슬라이드용)
1. **Generation이 아니라 Evaluation이 핵심** — 생성은 누구나 한다. 우리는 반려한다.
2. **이론이 코드 구조에 직접 매핑** — PREG(생성) / INQUISITIVE(필터) / EVPI(채점) / Politeness(톤).
3. **Human-in-the-loop** — 언제 쓸지(버튼), 어떻게 말할지(톤 다이얼)는 인간이 결정.

### 2.3 타깃 (MVP)
- 1차: **대학 팀플·스타트업·주니어 직장인**의 텍스트 회의록/메신저 로그.
- 데모 시나리오 2개만 깊게: **의사결정 교착**, **문제 원인 고착**.

## 3. 이론 → 제품 매핑 (통합 프레임)

### 3.1 3단 구조 (기획안_1의 연구 프레임을 제품 코어로 채택)

| 질문 | 이론 | 제품 모듈 |
| --- | --- | --- |
| **왜** 던지나 | Guided Team Reflexivity / Team Learning | “성찰 개입” 포지셔닝, Reasoning 배지 |
| **무엇을** 던지나 | Inquiry, Constructive Controversy, Representational Change, Double-loop | Questioning Operator + 회의목적 프리셋 |
| **언제** 던지나 | Bottleneck + Iqbal & Bailey 중단점 | MVP: 수동 / Post-MVP: 자동 |

### 3.2 MVP 회의 목적 프리셋 (기획안_1.1/3에서 축소)

전체 7개 목적을 다 구현하지 않는다. **심사 데모 완결성**을 위해 2개만 고정한다.

| 프리셋 | 회의에서 흔한 병목 | AI 질문 역할 | 이론 |
| --- | --- | --- | --- |
| **A. 의사결정** | A/B 충돌, 기준 부재, 성급한 합의 | 판단 기준·trade-off·반증 조건 명료화 | Inquiry + Constructive Controversy |
| **B. 문제 해결** | 증상=원인 착각, 가설 고착, 잘못된 문제정의 | 가정·문제표상 재구성(Reframing) | Double-loop + Representational Change |

나머지 5개(진행점검, 아이디어탐색, 전략, 회고, 합의정렬)는 **로드맵 카드**로만 제시한다.

### 3.3 Questioning Operator (생성 시 허용 유형)
MVP에서 생성기가 쓸 수 있는 질문 연산자(최대 5종):
1. **Assumption Challenge** — 넘어간 전제 노출  
2. **Reframing** — 문제 정의 재질문  
3. **Criterion Clarification** — “무엇을 기준으로 고르나”  
4. **Counterfactual / Pre-mortem** — “틀렸다면 / 실패했다면”  
5. **Constraint Relaxation** — “이 제약이 없다면”

가드레일: **사람 공격 금지**, **유도 질문(Loftus) 블랙리스트**, **닫힌 추궁형 최소화** (편도체 납치 방지 — 질문이론_2).

## 4. 핵심 기술: 질문 평가 파이프라인 (MVP 구현 스펙)

### Stage 0 — 입력
- 사용자가 회의 로그(텍스트) 붙여넣기 + 회의 목적 프리셋 선택(A/B) + 톤 단계 선택.
- STT/Vision **제외** (지연·오류·심사 리스크).

### Stage 1 — 후보 생성 (PREG 6트리거)
발화 구간에서 인지적 불균형 신호를 탐지해 후보 질문을 만든다.
- 지식 공백 / 모순 / 이상현상 / 불일치 / 예상 밖 결과 / 목표 장애  
→ 가정 노출은 여기(특히 모순·불일치)에서 처리.

### Stage 2 — 필터 (INQUISITIVE 3게이트)
1. 완결된 유효 질문인가  
2. 현재 구간과 관련 있는가  
3. 최근 N턴에 이미 답이 있지 않은가 (**비중복성**)

### Stage 3 — 가치 채점 (EVPI / Rao & Daumé 구조)
질문을 직접 “정보이득 높아?”라고 묻지 않는다.  
**가상 답변을 먼저 생성**한 뒤, 그 답이 **다음 행동·결론을 바꾸는지**를 채점한다.  
norm은 하나로 고정: **“결정/다음 액션이 뒤집힐 가능성”**.

### Stage 4 — 깊이 보정 (경량)
Graesser 깊은 질문 유형이 아니면 감점 또는 재작성. (확인형·정의형 감점)

### Stage 5 — 톤 변환 (Brown & Levinson 4단계)
| 단계 | 라벨(UI) | 예시 방향 |
| --- | --- | --- |
| 1 | 직설 | bald on-record |
| 2 | 명확·존중 | 적극적 정중함 |
| 3 | 부드럽게 | 소극적 정중함 |
| 4 | 우회 | off-record |

기본값: **2 또는 3** (조직 안전 우선). 부정 전제 변주(QDM)는 Post-MVP.

### Stage 6 — 출력 / 의도적 반려
- 카테고리(예: 맹점 / 본질 / 확장)별 **임계값 통과 최우수 1개**만 제시.
- 각 질문에 **채점 근거 배지** (정보이득 · 비중복 · 관련성 · 깊이).
- 전부 미달 시:  
  **“현재 맥락에서 유효한 질문이 발견되지 않았습니다 (의도적 반려)”**  
  → Wrapper가 아니라 Judge임을 UI로 증명.

## 7. UX 원칙 (심사·투표용 인상)

1. **메신저/회의록 스크립트 UI** — “붙여넣기 폼”이 아니라 대화 맥락이 보이게.  
2. **진단 버튼 1개** — “현재 대화 진단하기”.  
3. **결과 카드 ≤ 3개** — 많으면 요약 AI와 같아 보인다.  
4. **근거 배지 필수** — 인지 퇴화 비판 대응 + 학습 도구 포지션.  
5. **반려 화면을 부끄러워하지 말 것** — 이것이 핵심 차별점.  
6. **톤 다이얼을 전면 배치** — 정치적 맥락/위협 질문 리스크의 휴먼 루프 증명.

## 11. 제출용 요약 (복붙용)

**프로젝트명:** Q-Agent  

**해결하려는 문제:**  
회의에서 참석자들은 인지적 맹점과 심리적 부담으로 핵심 질문을 던지지 못하고, 기존 회의 AI는 질문을 생성할 뿐 “좋은 질문”을 판별하지 못해 중복·피상적 질문을 반복합니다.

**솔루션:**  
회의 텍스트를 분석해 후보 질문을 만든 뒤, 비중복·관련성 필터와 EVPI(답변이 다음 행동을 바꾸는가) 채점을 통과한 질문만 톤에 맞춰 제시합니다. 기준 미달 시 의도적으로 출력하지 않습니다.

**AI 활용:**  
LLM 기반 다단계 에이전트 파이프라인(생성→필터→가상답변·채점→톤 변환).  

**MVP:**  
웹 배포, 텍스트 입력, 의사결정/문제해결 프리셋, 톤 다이얼, 근거 배지, 의도적 반려.

## 12. 통합 결론

여러 기획안이 말하던 것은 결국 하나다.

> **Q-Agent는 회의의 Guided Reflexivity를 수행하는 Evaluation-first 질문 에이전트다.**

이론 조사는 “왜 이길 수 있는지”를 증명하고,  
초고의 제품 스케치는 “무엇을 보여줄지”를 고정하며,  
질문이론 기획안은 “6일 안에 무엇을 코드로 옮길지”를 결정한다.

**지금 할 일:** D0 스펙 고정 → D4 접수·배포 → D6 제출.  
기능 욕심보다 **배포된 Judge 파이프라인 하나**가 수상 확률을 만든다.
